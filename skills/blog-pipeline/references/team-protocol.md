# 팀 통신 프로토콜

SKILL.md의 되돌림 경로 표를 실제로 주고받을 때 쓰는 형식과, 리드가 중계하는 경우를 모았습니다. 팀원 쪽 형식은 각 에이전트 정의의 `## 팀 통신 프로토콜` 절에도 들어 있어요. 형식을 고칠 때는 이 파일과 해당 에이전트 정의를 함께 고칩니다.

## 메시지 형식

```
[{구간} {n}회차] {보내는 쪽} → {받는 쪽}
- {파일}:{줄} | 현재: {본문 진술} | 근거: {출처와 그 출처가 말하는 것} | 기대: {바뀌어야 할 모습}

[재확인 요청 {구간} {n}회차] {받는 쪽} → {보내는 쪽}
- {파일}:{줄} | 처리: 고침 또는 못 고침({이유}) | 새 사실: 있음 또는 없음
```

리드가 보내는 요청은 두 가지입니다. 근거 사슬은 `[근거 사슬 {n}회차] main → blog-verifier`, 사용자 결정은 `[사용자 결정 {n}회차] main → blog-writer`로 시작해요. editor에게 재점검을 맡길 때는 `[사용자 결정 {n}회차 재점검] main → blog-editor`를 보냅니다.

## 되돌림 기록

회차를 닫는 팀원이 `_drafts/{slug}.research.md`의 `## 되돌림 기록` 절에 한 줄씩 남깁니다(절이 없으면 만든다). publisher가 노트를 포스트와 함께 커밋하므로 기록이 저장소에 남아요.

```
- {구간} {n}회차 | {보내는 쪽} → {받는 쪽} | 항목 {N}건 | 해소 {N}, 남음 {N} | {줄 목록}
```

## 리드가 중계하는 경우

- **사용자 결정 회신**: writer는 이 구간만 main으로 회신합니다(`[완료] 사용자 결정 {n}회차`). 회신에 `새 사실: 있음` 줄이 있으면 리드가 그 줄을 근거 사슬 회차로 verifier에게 먼저 보내요. verifier의 `[완료]`를 받은 뒤 editor에게 재점검을 보냅니다. 두 팀원에게 동시에 보내지 않아요
- **배열 회차의 새 사실**: editor의 `[완료]` 보고에 writer가 넣은 `새 사실: 있음` 줄이 있으면, 리드가 승인을 요청하기 전에 그 줄을 근거 사슬 회차로 verifier에게 보냅니다
- **초안 있음 경로**: writer가 없어서 writer 쪽 항목이 main으로 옵니다.
  - 초안에 `<!-- 작성자 노트`가 있으면 이전 파이프라인이 쓴 초안입니다. 리드가 그때 `blog-writer`를 처음 띄우고, 받은 항목과 회신할 팀원을 프롬프트로 넘겨요. writer가 재확인을 보낸 뒤부터 verifier와 editor는 writer와 직접 주고받습니다
  - 작성자 노트가 없으면 사용자가 쓴 초안이니 항목을 사용자에게 보입니다. 사용자가 정한 대로 리드가 고친 뒤, 보낸 팀원에게 재확인을 요청해요

## 시나리오: 팀 되돌림

### 세 구간이 한 번씩 도는 흐름
1. Phase 1.5: `blog-verifier`가 문장 하나로 못 고치는 주장 1건을 `blog-writer`에게 사실 교정 1회차로 보낸다. writer의 재확인 요청을 받아 확인하고, 기록을 남긴 뒤 `[완료]`
2. 리드의 근거 사슬 게이트에서 인용 1건이 검증 기록에 없다 → `SendMessage(to: "blog-verifier")` → 기록을 추가한 뒤 `[완료]`
3. Phase 2: `blog-editor`가 재료가 없는 우산 문장 1곳을 `blog-writer`에게 배열 1회차로 보낸다. 재점검 뒤 `[완료]`
4. 확인: 세션의 subagents transcript에 `blog-writer`, `blog-verifier`, `blog-editor`가 하나씩만 있고, 노트의 `## 되돌림 기록`에 세 회차가 있다

### 되돌림 중 팀원 멈춤
1. 사실 교정 1회차를 받은 `blog-writer`가 오류로 멈춘다. `blog-verifier`는 `[대기] blog-writer` 상태다
2. 리드가 `SendMessage(to: "blog-writer")`로, 받은 요청을 이어서 처리하라고 보낸다
3. writer가 자기 transcript에서 이어 고치고 `blog-verifier`에게 재확인을 요청한다. 새 스폰은 없다

## 설치 뒤 확인

버전을 올리고 설치본을 갱신한 다음, 세션을 다시 시작한 뒤에 합니다. 0.2.0과 비교하려면 리드 세션을 Opus로 띄웁니다. 0.2.0은 모든 호출에 opus를 명시했기 때문이에요.

1. 대상: writer까지만 끝나 `## 검증 기록`이 없는 진행 중 초안. 발행 직전이 아닌 것으로 고른다. 초안 있음 경로라 Phase 1.5부터 돌고, 작성자 노트가 있으면 writer 쪽 첫 항목이 올 때 `blog-writer`가 처음 스폰된다
2. 새 스폰이 없었는지: `~/.claude/projects/{cwd 슬러그}/{세션 ID}/subagents/*.meta.json`의 `name`이 팀원마다 하나씩이고, `-2`로 끝나는 이름이 없다
3. 회차가 남았는지: 노트의 `## 되돌림 기록`에 회차마다 한 줄씩 있다. 저절로 생긴 회차가 없으면 같은 세션에서 "윤문만 다시"를 요청하고, `blog-editor`가 `SendMessage`로 재개되는지 본다
4. 토큰: 아래 명령으로 에이전트별, 회차별 사용량을 뽑는다. 되돌림 회차(wake 2부터)의 증분을 같은 에이전트 wake 1과 나란히 놓는다. wake 1은 새로 스폰했다면 들었을 초기 읽기 비용이다. 사용자를 기다린 뒤의 회차는 캐시 만료로 cache_creation이 커지니 따로 적는다

```bash
python3 "$(find ~/.claude/plugins -path '*sr-blog-harness*/scripts/team_token_usage.py' | head -1)" ~/.claude/projects/{cwd 슬러그}/{세션 ID}
```
