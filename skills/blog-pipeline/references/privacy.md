# 리서치 노트의 개인 정보

리서치 노트(`_drafts/{slug}.research.md`)는 포스트와 같은 커밋으로 공개 저장소에 올라갑니다. 근거 사슬을 남기려고 커밋하는 파일이지만, 커밋하는 순간 누구나 읽을 수 있어요. push한 뒤에는 파일을 고쳐도 git 이력과 PR 기록에 원래 내용이 남습니다. 그래서 노트에는 처음부터 공개해도 되는 값만 적고, 발행 직전에 한 번 더 점검합니다 (#13).

## 싣지 않는 것

| 종류 | 예 | 노트에 적는 방식 |
|---|---|---|
| 절대 홈 경로 | `/Users/{이름}/...`, `/home/{이름}/...` | 공개 저장소면 저장소 기준 경로(`flowcast/skills/...`), 아니면 `~/` 기준 경로나 일반 라벨 |
| 비공개 저장소 이름 | 작성자 계정의 private 저장소 | "작성자의 비공개 지침 저장소"처럼 종류만 밝힌 라벨 |
| 비공개 저장소의 커밋 해시 | `0a1b2c3` | "비공개 저장소의 첫 커밋"처럼 순서나 시점으로 부른다 |
| 비공개 파일의 줄번호 | `CLAUDE.md:95` | 파일의 역할로 부른다 ("전역 지침의 전후 예문") |
| 세션 기록 경로 | `~/.claude/projects/...` | "세션 기록" |
| 이메일, 사내 정보 | 개인 주소, 사내 경로와 클래스명 | 싣지 않는다. 사내 코드는 재구성 예제 규약을 따른다 |

공개 저장소(블로그 저장소, 공개 플러그인)의 경로, 커밋, 줄번호는 그대로 적습니다. 독자가 직접 열어 대조할 수 있는 근거라서 오히려 남겨야 해요.

## 원본은 따로 둔다

비공개 출처를 되짚어야 할 때가 있습니다. 그때는 원본 경로와 줄번호를 `_drafts/{slug}.sources-internal.md`에 적습니다. 블로그의 `.gitignore`는 `_drafts/*`를 무시하고 `*.research.md`만 다시 추적하므로, 이 파일은 커밋되지 않아요. 파일 이름을 `.research.md`로 바꾸는 순간 공개되니 주의합니다.

## 누가 언제 지키나

| 단계 | 하는 일 |
|---|---|
| researcher | 노트에 출처를 적을 때 위 표의 방식으로 적는다. 비공개 원본은 `.sources-internal.md`에 둔다 |
| verifier | `## 검증 기록`의 서지/출처 줄도 같은 방식으로 적는다. 확인은 원본으로 하고, 기록에는 라벨을 쓴다 |
| publisher | 커밋 전에 `scripts/privacy_check.py`로 포스트와 노트를 점검한다. 출력이 있으면 커밋하지 않고 리드에게 보고한다 |

## 점검 스크립트

```bash
python3 "$(find ~/.claude/plugins -path '*sr-blog-harness*/scripts/privacy_check.py' | head -1)" \
  _posts/{date}-{slug}.md _drafts/{slug}.research.md
```

- 절대 홈 경로, 세션 기록 경로, 이메일, 작성자 계정의 비공개 저장소 이름을 찾습니다.
- 비공개 저장소 목록은 `gh`로 받습니다. 받지 못하면 `알림:` 줄을 내고 나머지 점검만 합니다.
- 한 단어 저장소 이름(예: `spring`)은 본문의 일반 단어와 겹치므로, `계정/이름`이나 "이름 저장소"처럼 저장소로 읽히는 자리에서만 찾습니다.
- 스크립트는 판정하지 않습니다. 인용한 공개 문서 속 경로처럼 공개해도 되는 값이 걸릴 수 있어요. 그 판단은 리드가 사용자와 합니다.
